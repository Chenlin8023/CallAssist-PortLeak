## 一、当前状态（一句话）

BioProtect（4.6 roothide 破解版）在 SpringBoard 内泄漏 mach 端口，超过每进程上限 **131072** 后被系统强杀（EXC_RESOURCE/PORT_SPACE）→ 表现为"跑十几个小时后桌面注销"。修复模块 **BioProtectLeakGuard** 已迭代到 **2.0.4**：2.0.1–2.0.3 因"零 substrate 依赖"从未被设备加载器注入（日志全空的根因），2.0.4 已恢复 substrate 直连、形态与设备上确认可加载的 VolMan 完全一致，**但截至收工，`com.local.bioprotectleakguard.plist`（影子日志）仍未出现，2.0.4 安装结果未确认**。

## 二、已确认事实（硬结论，勿重复推导）

1. **死因实锤**：`ExcResource_SpringBoard-2026-10-23-204635.ips` 的 termination 字段：
   `namespace=PORT_SPACE / indicator=(Limit 131072 ports) Exceeded system-wide per-process Port Limit / signal=SIGKILL`。
   即 SpringBoard 的 mach 端口数触顶被 jetsam 强杀。注意触发的是**端口**上限，不是 fd 上限。
2. **BioProtect 的泄漏点**（4.6-222 逆向，report 05）：
   - 泄漏 A（端口）：`BioProtect.dylib` 两处 CFUserNotification（`sub_95f4`、`sub_479d8`），创建后全二进制无任何 Cancel/RemoveSource。
   - 泄漏 B（fd）：`sub_4a59c`/`sub_4f2bc` 的 `open` 无 `close`，被 kevent 文件监听回调高频触发。
   - 已排除：notify_register_check（token 全全局，一次性）、XPC（构造函数只建一次）。
3. **LeakGuard 2.0.1–2.0.3 从未被加载**（日志全空的真正原因）：
   - 崩溃日志 usedImages 中**没有 BioProtectLeakGuard.dylib**；同时 SpringBoard 加载的 40+ 个 tweak（BioProtect×4、VolMan、Lynx2_CN、Crane、Immortalizer、SHELLX 等）**全部导入 MSHookFunction/MSHookMessageEx 并链接 substrate**。
   - LIEF 对比：LeakGuard 2.0.3（设备）依赖仅系统库、无 MSHook 导入；VolMan（设备，可加载）含 `@rpath/CydiaSubstrate.framework/CydiaSubstrate` 依赖 + MSHook 导入；BioProtect 转换版含 `@loader_path/.jbroot/usr/lib/libsubstrate.dylib`。
   - **结论：RootHide + Orion + ElleKit 只加载"导入 MSHook 符号并链接 substrate"的 tweak**。2.0.2/2.0.3 的"去 substrate"路线从方向上是错的。
4. **2.0.4 已修复形态**：恢复 `#include <substrate.h>` 直连 `MSHookFunction`；构建后 LIEF 复核 = arm64 单切片 + 导入 `_MSHookFunction` + 依赖 `@rpath/CydiaSubstrate.framework/CydiaSubstrate`（与 VolMan 完全同形）+ 版本串 2.0.4。build.sh 增加两条防回归断言。

## 四、下次接手的精确步骤

**前置判断（二选一，先确认再动作）**：
- 若用户**还没装 2.0.4**：`com.local.bioprotectleakguard.plist` 不存在是**预期现象**（2.0.3 及以前从不生成），直接跳第 1 步。
- 若用户**已装 2.0.4 并 respring 后仍无 diaglog**：不要重新推导根因，先收集以下证据再判断：
  1. Sileo 已安装列表里 BioProtect Leak Guard 的**版本号**（应为 2.0.4）；
  2. Filza 确认 `/Library/MobileSubstrate/DynamicLibraries/BioProtectLeakGuard.{dylib,plist}` 存在且 dylib 大小 ≈ 71,776 B；
  3. 是否真的 respring 过（dylib 只在 SpringBoard 启动时加载）；
  4. 转换后的 deb 是否包含 `.roothidepatch` 标记（`BioProtectLeakGuard.dylib.roothidepatch`）。

**正常流程（确认已装 2.0.4 且 respring 后）**：
1. Filza 打开 `/var/mobile/Library/Preferences/`，找 `com.local.bioprotectleakguard.plist`（文件名以 com.local. 开头，不是 BioProtectLeakGuard）；
2. 打开看 `diaglog` 键：
   - 首行 `[boot] v2.0.4 pid=… 已进入构造函数` → **加载成功**，读 `stat ports=… fd=… cf_called=… cf_adopt=… cf_free=… fd_open=… fd_close=… fd_skip=…` 曲线发回；
   - `ports=` 从单调上升变为平台/回落、`cf_free` 增长 → 修复生效；
   - `ports=` 仍线性涨但 `cf_adopt` 很少 → 泄漏源不止 CFUserNotification，用 `.ips` 的 usedImages（40+ 插件）逐个排查其它嫌疑（先看 BioProtectXS_CN / LimneosCrack / Lynx2_CN）；
3. 若 diaglog 仍为空 → dylib 仍未注入：检查转换是否成功、过滤器 plist 是否完整，必要时改用 Sileo 安装。

## 五、关键经验（防止下次重复踩坑）

1. **"装上没反应/没日志" ≠ 修复没生效，先确认 dylib 有没有被加载**：看崩溃日志 usedImages（`.ips` 的 `usedImages` 数组），或 `log show`。加载器静默跳过失败 dylib，不崩溃不报错。
2. **这台设备的加载器只认 substrate 链接形态**：RootHide + Orion + ElleKit 下，tweak 必须导入 MSHookFunction/MSHookMessageEx 并链接 substrate（`@rpath/CydiaSubstrate.framework/CydiaSubstrate` 或 `@loader_path/.jbroot/usr/lib/libsubstrate.dylib`）。"零依赖 dlsym"方案在此环境无效。防回归断言已写进 build.sh。
3. **RootHide 转换器会改写包内绝对路径字面量**：日志路径必须运行时拼（NSHomeDirectory/NSTemporaryDirectory）；CFPreferences 影子日志（diaglog 键）不经过路径，是最可靠的读取通道。
4. **杀的是端口不是 fd**：jetsam 的 indicator 明确指出 PORT_SPACE/131072。fd 泄漏也在，但先触顶的是端口。修复要两者都上（CF 清理 + fd 回收）。
5. Windows 侧解析 roothide deb：zstd 压缩需 `pip install zstandard`；LIEF 1.0 接口用 `m.libraries`/`m.imported_symbols`/`m.commands`。
