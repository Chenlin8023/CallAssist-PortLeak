2.0.7 真机证明 **isa 认证补丁完全成功**（SpringBoard/Spotlight/设置全部正常加载、ctor
全流程跑完，不再安全模式）；但 SpringBoard 运行 10.7 小时后仍被 jetsam 以

## 三、根因：定时器 ARC 生命周期 bug

```c
static void bplg_start_timers(void) {
    dispatch_queue_t q = dispatch_queue_create(...);   // 局部
    dispatch_source_t t = dispatch_source_create(...); // 局部
    dispatch_source_set_event_handler(t, ^{ ... 清扫+统计 ... });
    dispatch_resume(t);
}   // ← ARC 在这里释放 q 和 t，定时器销毁
```

该 bug 2.0.5 就存在，但 2.0.7 之前 dylib 从未成功进过 arm64e 系统进程，
所以从未暴露。**教训：`dispatch_source_t` 必须存全局（或强引用属性），
"resume 过的 timer 自己会活着"在 iOS 17 的 SB 里不成立（实测一次都不触发）。**

连带后果：hook 已装好但**清扫从不执行**——CF 通知被接管（CFRetain）后永不清扫，
等于只观测不回收；fd 记录表只进不出。比不装稍好的只有观测计数器与日志。

## 四、2.0.8 修复内容

1. **定时器全局持有**：`static dispatch_source_t t; static dispatch_queue_t q;`
   提升为文件级静态 + 防重入。修好后：+5s 出现「影子通道自验证」行 =
   引擎复活的可视证据；每 5 分钟出 stat 行。
2. **新增端口归因观测**（为"CF 清扫仍不够"做准备）：hook
   `mach_port_allocate`，统计：
   - `pa=` 进程内成功分配总数（基线）
   - `paBP=` 其中调用方在 BioProtect 镜像内的次数
   - `bp_sites=` BioProtect 内 Top8 调用点 `镜像+偏移:次数`
   钩子路径只做原子计数 + ra 缓存查表（复用 gCallerCache），不做 IO。
   **若 2.0.8 之后端口曲线仍上涨，stat 行直接点名泄漏函数**，拿偏移到
   `bioprotect-analysis/dumps_46/` 的反汇编里对号即可。
3. 版本串/断言/说明全部更新。isa 认证补丁流程原样保留。
